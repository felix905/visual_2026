# MIGRATION

## 1. GUIDING RULE

The current project should be treated as a legacy source layer. It remains intact and must not be modified. The V2 project is a separate blueprint and future implementation area.

## 2. CURRENT PROJECT STATUS

The live project already contains useful material for reuse, including:
- educational positioning
- lead-generation flows
- CTA structures
- some audience-specific landing pages
- visual and logo assets

However, the current content does not yet match the proposed architecture for:
- Colegios
- Empresas
- Familias
- Recursos
- Nosotros
- Contacto

## 3. RECOMMENDED MIGRATION APPROACH

### Preserve and review
Preserve the following for later evaluation:
- brand assets and logo variants
- existing messaging that is still aligned with Visium’s educational mission
- direct CTA patterns
- contact and inquiry flows
- proven structure of landing pages and callouts

### Reassess before migration
Before reusing anything, confirm:
- whether the current audience framing still matches the business brief
- whether the copy is current and legally/commercially safe
- whether any metrics or testimonials are still valid
- whether the offer structure matches the V2 audience model

### Rewrite or replace
The following items should not be carried directly into V2 without review:
- historical statistics
- pricing claims that are not attached to a validated source
- generic course pages that do not support a clear audience path
- mixed page taxonomies that do not fit a future conversion architecture

## 4. CONTENT MIGRATION PRIORITY

### Highest priority
- Home
- Colegios
- Empresas
- Familias
- Contacto

### Secondary priority
- Nosotros
- Recursos

### Lower priority
- historical campaign pages
- non-core landing pages that served prior experiments or short-term campaigns

## 5. MIGRATION DECISION PROCESS

For each piece of content, classify it as one of:
- preserve
- adapt
- rewrite
- remove / deprioritize
- validate first

Any item with unresolved business or data uncertainty should be marked:
- [BUSINESS DECISION REQUIRED]

## 6. REQUIRED BUSINESS VALIDATION BEFORE IMPLEMENTATION

The migration process should not proceed without checking:
- pricing by audience
- current testimonial status
- current case study availability
- whether the family claim is still operative
- official logo and color source assets
- final route naming and structure

## 7. SAFE PHASED APPROACH

### Phase 01 — blueprint only
- audit current project
- create structural docs
- identify reusable vs outdated content
- document business decisions required

### Phase 02 — implementation
- build the V2 structure only after the docs are approved
- keep the current site as the preserved legacy version
- implement the new site in a distinct V2 area

## 8. FINAL MIGRATION NOTE

The existing project is a valuable base but not a final V2 design source. It should be treated as a collection of historical and contextual assets, not as the final architecture. Migration should be selective, evidence-based, and grounded in the audited brief rather than in legacy assumptions.
